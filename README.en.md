# I Ching LLM Divination 🔮

Traditional Chinese six-line (hexagram) divination with AI interpretation. Toss three coins six times, and let the I Ching Sage interpret your hexagram.

Fully local deployment. **You choose the LLM** — any service or local model supporting the OpenAI-compatible API works.

## Features

- 🪙 **Authentic coin-cast divination**: three coins, six tosses. Old yang/old yin are moving lines; the changing hexagram is computed automatically
- 📜 **Complete 64-hexagram table**: names, symbols, and judgments built in (zero dependencies)
- 📖 **Classical text included**: the hexagram judgment, line texts and image are injected into the prompt, so the LLM reads from the source instead of improvising
- 🧠 **Bring your own LLM**: configure via environment variables — local Ollama / Gemma / DeepSeek / OpenAI / Qwen, anything OpenAI-compatible
- 📚 **Optional RAG enhancement**: point `ICHING_RAG_DIR` at a folder of `.md`/`.txt` files for knowledge-base retrieval. Skip it and it's pure LLM interpretation
- 🌐 **Bilingual UI**: 中文 / English toggle
- 🖥️ **Responsive web UI**: works on desktop and mobile

## Quick Start

```bash
# 1. Install dependencies
pip install -r requirements.txt

# 2. Configure your LLM (env vars)
export LLM_BASE_URL=http://localhost:11434/v1   # local Ollama, for example
export LLM_API_KEY=
export LLM_MODEL=qwen2.5:7b

# 3. Run
cd backend
uvicorn app:app --host 0.0.0.0 --port 8088
```

Open http://localhost:8088 , hold your question in mind, toss the coins six times, and receive the interpretation.

### LLM configuration examples

| Backend | LLM_BASE_URL | LLM_MODEL |
|---|---|---|
| Local Ollama | `http://localhost:11434/v1` | `qwen2.5:7b` |
| Local Gemma (MLX) | `http://localhost:8080/v1` | `gemma-4-26b-a4b-it` |
| DeepSeek | `https://api.deepseek.com/v1` | `deepseek-chat` |
| OpenAI | `https://api.openai.com/v1` | `gpt-4o` |
| Qwen (DashScope) | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-max` |
| Any OpenAI-compatible server | your URL | your model |

The `lang` field in the request controls interpretation language (`zh` or `en`). The web UI has a toggle.

## Optional RAG

```bash
# Point at a folder of .md/.txt files to enable knowledge retrieval
export ICHING_RAG_DIR=/path/to/your/knowledge
```

When the question matches content in the knowledge base, relevant excerpts are injected into the interpretation. Without it, the LLM interprets from the built-in classical text alone. (RAG is zh-only; English mode uses the built-in English judgments.)

## API

- `GET /api/health` — service status + LLM/RAG config
- `POST /api/iching` — cast and interpret

```json
{
  "tosses": [{"coins": [1,1,0]}, {"coins": [0,1,1]}, {"coins": [1,1,1]}, {"coins": [0,0,0]}, {"coins": [1,0,1]}, {"coins": [0,1,0]}],
  "question": "How will my career go this year?",
  "lang": "en"
}
```

Returns the hexagram, moving lines, changing hexagram, and the full interpretation.

## Text sources & copyright

- The Chinese hexagram texts (judgments, line texts, images) come from the received text of the *Zhouyi* (*I Ching* / *Book of Changes*), a classical work over two thousand years old — public domain. The Chinese texts have been checked line-by-line against the received text for key hexagrams.
- The English judgments and images are **our own rendering**, informed by the interpretative tradition of the public-domain Wilhelm translation (1923); they are not verbatim Wilhelm text (the English Wilhelm/Baynes edition, 1950, is not yet public domain). Line texts are not shipped in English — in English mode the LLM reads the Chinese originals and interprets in English.
